# Microservices Design Document

## Requirement Mapping

The system implements a backend-only Employee Leave Management Portal with JWT authentication, role-based authorization, leave balances, application workflow, manager approval/rejection, leave history, and notification logging.

## Architecture

```text
      |
      v
+-------------------+
| API Gateway :8080 |
+-------------------+
   |        |        |

Auth     Leave    Notification

     | Eureka     |

RabbitMQ :5672 <--- Leave Service publishes notification events
RabbitMQ :15672 --- Management UI
```

## Service Responsibilities

### discovery-service
- Runs Eureka Server.
- All microservices register themselves.

### api-gateway
- Uses Spring Cloud Gateway.
- Routes `/auth/**`, `/leaves/**`, and `/notifications/**` to registered services.

### auth-service
- Contains predefined users.
- Generates JWT on successful login.
- JWT includes `userId`, `role`, `managerId`, subject, issued-at, and expiration.

### leave-service
- Validates JWT for every protected endpoint.
- Enforces employee/manager access boundaries.
- Maintains in-memory employees, leave requests, and leave balances.
- Automatically initializes leave balances when employees are created:
  - Casual Leave: 12 days
  - Sick Leave: 10 days
  - Privilege Leave: 15 days
- Performs validations:
  - Sufficient balance
  - No overlapping active leave requests
  - No past dates
  - Start date must be before or equal to end date
- Deducts leave balance only after manager approval.

### notification-service
- Consumes RabbitMQ notification events.
- Logs notifications.
- Maintains in-memory notification history by user.

## Cross-Cutting Concerns

| Concern | Implementation |
|---|---|
| Authentication | JWT generated by auth-service |
| Authorization | Role + user/team validation inside leave-service |
| Service discovery | Eureka |
| API Gateway | Spring Cloud Gateway |
| Async communication | RabbitMQ |
| Circuit breaker | Resilience4j around notification publishing |
| Logging | SLF4J logs across services |
| Exception handling | Global exception handlers with structured errors |
| Health checks | Spring Boot Actuator `/actuator/health` |
| Containerization | Dockerfile per service + docker-compose |

## Assumptions

- Database is optional for MVP, so in-memory repositories are used.
- Notification means log entry only; no email/SMS is integrated.
- Demo video is excluded as per instruction.
- One reporting manager is mapped for employee users in mock data.
